# 测试与验收矩阵

## 1. PR 基础门禁

每个 PR 至少验证：

| 领域 | 验证 |
| --- | --- |
| 后端 | Unit、全部 Integration 标签包、生产构建 |
| 前端 | Typecheck、Custom Vitest、生产构建 |
| 生成代码 | `go generate ./cmd/server` 后无差异 |
| Lint | 仅检查相对显式官方基线的新问题 |
| 差异边界 | Candidate Tree 与差异台账一致 |
| 薄桥边界 | 112 个契约路径、精确行预算、影子目标和结构规则一致 |
| 数据库 | Migration、Schema 和例外表语义门禁 |
| Actions | Action Pin、权限和 Actionlint |
| 安全 | `govulncheck` 与生产依赖审计 |

`boundaries` 与后端、前端、Lint、Shell Job 在 `verify-target` 确认准确 SHA 后并行；
它仍是分支保护、Workflow 结论和 Release Preflight 的独立必需结果。后端 Integration
入口固定登记当前六个含标签测试的包：`internal/custom/subscriptioninventory`、
`internal/custom/subscriptionrepository`、`internal/middleware`、
`internal/pkg/tlsfingerprint`、`internal/repository`、`internal/server/routes`。契约测试
必须证明六包全部执行、新增标签包未登记时失败，且
无 Integration 标签的 `internal/service` 不进入日志；该入口不再通过 `./...` 重跑
普通 Unit 测试。

## 2. 内容审计范围

### 范围内

- 官方处罚、通知、计数和会话屏蔽保持一致；
- 并发命中不会丢失或重复累计；
- 管理页面状态和后端配置一致。

### 范围外

- 记录 `cyber_policy_out_of_scope`；
- 不通知、不累计、不封号、不写会话屏蔽；
- 日志摘要不包含 Token、密钥、完整 URL 或完整请求体。

### 动态变化

- 分组加入审计范围后下一请求进入官方处罚；
- 移出后下一请求进入范围外逻辑；
- 多实例配置刷新后行为一致。

### API 审计子范围

- 总范围内、API 子范围外的关键词命中仍被拦截，干净请求不调用审核 API；
- API 子范围内的干净请求按模式执行同步或异步 API 审计；
- 仅 API 策略只在 API 子范围执行，模型过滤继续同时约束关键词与 API；
- 旧配置缺少 `api_audit_scope` 时按总范围内全部分组处理；
- 总范围指定模式为空时仍可保存，且不触发关键词或 API 审计；
- API 指定范围为空或包含总范围外分组时拒绝保存；
- 已删除分组残留在历史总范围或 API 子范围时，前端加载和后端保存均自动剔除，不阻塞
  其他设置修改；新提交的不存在分组仍拒绝，分组仓库异常原样上抛；
- 总范围移除分组时前端同步清理 API 子范围；仅关键词策略禁用控件但保留配置；
- 异步任务执行前复核最新 API 子范围，已移出的分组不调用审核 API；
- 缩减 worker 数时，已出队任务继续处理完成，最新 worker 数只约束下一轮取任务。

### 用户专属封禁阈值

#### 自动化测试

- 旧配置缺少 `user_ban_thresholds` 时返回空列表；PUT 省略字段保持原值，传空列表清空；
- 用户 ID 必须为正整数且唯一，阈值必须为 `1-1000` 的整数，非法配置拒绝保存；
- 匹配用户使用专属绝对阈值，未匹配用户使用默认值；默认值变化不改写专属值；
- 保存阈值不立即扫描或封禁，下一次普通审计或 `cyber_policy` 命中才执行判定；
- 实际阈值同步进入命中提醒、封禁邮件和 `ban_threshold` 模板变量；管理员豁免不变；
- `cyber_policy` 排除计数时不执行处罚或违规次数查询，通知仍独立解析实际阈值；
- 前端覆盖配置加载与保存、搜索新增、重复结果过滤、并发选择单飞、管理员/已删除用户
  拒绝新增、缺失历史项回显移除、逐行校验、空列表清除、`Esc` 关闭和新增后焦点；
- 本次 diff 未新增 Migration、Schema、实体字段或 SQL 变化；Candidate Tree 中的历史
  数据库差异继续由已批准例外和语义指纹校验。

#### 人工交互与响应式验收

- 在窄屏下每行纵向排列，邮箱、用户 ID、输入框和删除按钮无横向遮挡；
- 仅使用键盘可完成搜索、选择、阈值编辑和删除，焦点顺序清晰且错误信息可感知；
- 保存成功与失败反馈在亮色、暗色及窄屏布局下可见。

#### 待补自动化测试

- 浏览器级响应式截图、完整 Tab 焦点顺序和屏幕阅读器语义继续保留为待补 E2E 覆盖。

## 3. 公开 Release 更新

### 来源

- 更新源固定为 `o87110/sub2api-custom-public`；
- 请求参数、环境变量和缓存不能切换仓库；
- 未配置 Token 时可匿名读取 Release 与资产；
- 可选 Token 只发送到受信任 GitHub API，重定向后被剥离；
- 自定义源失败不能安装官方资产。

### 下载与安装

- 只接受合法 `vX.Y.Z-custom.N`；
- 拒绝非 HTTPS、错误仓库、查询参数、片段和未批准主机；
- 强制最大尺寸与 SHA256；
- 拒绝路径穿越、符号链接和额外文件；
- `--version` 与目标 Tag 不一致时拒绝替换；
- 替换失败恢复原二进制和备份。

### 缓存与版本

- 缓存绑定仓库和完整版本；
- 跨仓库、过期、旧格式和污染缓存被拒绝；
- `has_update` 使用完整自定义版本；
- `has_official_update` 使用基础版本；
- 官方查询警告不覆盖自定义 Release 信息。

## 4. runtime 持久化

- 空 runtime 从镜像基线初始化；
- 合法 runtime 在容器重建后保持；
- 目录、符号链接、空文件、错误权限和版本不匹配被拒绝；
- 更新后 `/proc/1/exe` 指向 `/app/runtime/sub2api`；
- 重建前后 SHA256 一致；
- `.backup` 回退路径通过故障注入验证。

## 5. Release 与 GHCR

- Tag 指向预期 `main` 提交且不可变；
- 最新接受的 CI 和 `boundaries` Job 成功；
- Preflight 复用同一准确 SHA 的成功证据，Release `context` 不重复 Candidate Tree、
  差异台账或数据库语义门禁；
- Build Job 无发布权限；
- 自动路径仅在 Release 输入变化时发布；普通文档、测试和 Workflow 单独变化时跳过，
  首次发布、可信手工调度、Vendor 基线升级和未完成 Tag 重试仍继续；
- 前端 Artifact 必须唯一绑定准确 CI Run、Workflow、事件、`main`、Head SHA、ID、
  Digest 和未过期状态；缺失或过期本地重建，重复或来源/结构/Digest 异常失败；
- Artifact ID、Digest、Manifest 和文件 SHA256 一致；
- 新 `sub2api-custom-release/v1` Manifest 必须包含 `build_inputs.frontend`，历史 v1 可
  缺少；Payload Metadata 的前端来源必须与 Manifest 完全一致；
- Release 资产集合精确且无重复；
- OCI Index 包含 `amd64` 与 `arm64`；
- GHCR 多架构及架构标签解析到预期 Digest；
- 不产生 `latest` 或其他浮动标签；
- 已发布资产不能覆盖；
- Release 或 GHCR 任一不完整时版本不可部署。

Buildx 使用固定 `sub2api-release-oci-v1` GHA Cache scope。缓存缺失或不可用只允许冷
构建，缓存命中与否不参与信任判断；生产构建、双架构 Manifest、checksum 和 Digest
校验不能省略。每次新 Release 在 Step Summary 分别记录前端准备、GoReleaser、OCI、
Artifact 上传和发布耗时。上线后至少比较五次新 Release；CI 中位数目标不高于
380 秒，Release 中位数不高于 360 秒。若 OCI 缓存无收益，只移除缓存配置。

## 6. 公共 PR 与权限

- Fork PR 只有只读权限且没有 Secrets；
- `pull_request_target` 不执行带写权限的 PR Head 代码；
- 升级候选代码只在只读、无 Secrets Job 中运行；
- 最终收尾只允许受信任 `main` 的手动调度；
- Workflow 文件被候选分支修改时拒绝可信调度；
- Release、Package 和 Environment 权限不能由 PR 输入扩大。

## 7. 官方升级

- 官方 Tag 从 `Wei-Shaw/sub2api` 隔离引用解析；
- `upgrade/vX.Y.Z` 必须基于最新 `main`；
- 工作流、差异台账和保护路径变化被识别；
- 数据库变化必须产生人工评审；
- 冲突分支保留，不重置、不强推；
- 后端、前端、Release 预构建全部通过；
- 合并后准确更新 `refs/heads/upstream/main`（本地为 `origin/upstream/main`）与
  `vendor-X.Y.Z`；
- 准确合并 SHA 的 CI 完成后才允许发布 `custom.1`。

薄桥门禁还必须用无外部依赖夹具证明以下情况会失败：漏登记薄桥、缺少必需影子
映射、超出精确增删预算、DTO/Wire 引入控制流、`delegate/view` 中未登记的新函数、
改名循环、普通条件分支、Watcher、重试、协调函数或无控制流多步骤函数，以及支付、
最低余额和管理表单的旧高风险业务函数重新出现在官方桥中。允许结构必须精确绑定
路径、所属函数和完整控制语句；相对 Vendor 新增的调用面还必须精确绑定所属函数或
模板事件位置、执行目标与次数，证明已有函数中追加直接、括号、可选或计算属性调用、
新增模板事件处理器或重复一次已批准调用都会失败，并保留正向夹具。

## 8. API 密钥当前页批量操作

- 表格逐行选择和全选仅覆盖当前页；
- 分页、页大小、筛选、排序和手动刷新会清空选择；
- 分组操作要求选择可用分组，并跳过已经属于目标分组的密钥；
- 全部选择停用项时显示“批量启用”，确认后调用单密钥状态接口并发送 `active`；
- 全部活跃或混合选择时显示“批量禁用”，混合选择只发送活跃项；`inactive`、
  `expired` 和 `quota_exhausted` 均保持原状态并使用通用跳过数量文案；
- 启用、禁用和删除在确认前不发送请求；启用确认使用非危险样式并说明会立即恢复
  调用能力，禁用和删除保持危险样式；
- 批量执行并发硬上限为 5，即使传入更高并发也不得突破，重复 ID 只处理一次；
- 全部成功后清空选择，部分失败或全部失败仅保留失败项供重试；
- 结果提示只包含成功、跳过和失败数量，不包含密钥或敏感错误；
- 删除非首页的全部当前页行后回退到上一页，部分删除失败时留在当前页；
- 桌面端批量操作栏与表格之间的布局保持 `flex-1 min-h-0` 高度约束，本页行数超过
  可视区域时表格内部可以纵向滚动，所有当前页行均可访问；
- 亮色、暗色、窄屏、键盘焦点和复选框可访问标签均可用。

## 9. 支付宝/微信多渠道

- `checkout-info` 同时暴露四个稳定渠道，易支付排序在官方之前，单渠道仍显示具体
  渠道；
- 同服务商多个实例折叠为一个选项并继续负载均衡，不同服务商的币种、费率和限额
  不混合；充值单笔限额按本金加手续费后的网关实付金额判断，显式渠道全部实例超限
  时失败关闭；
- 同渠道实例的单笔区间为 `1–10`、`20–100` 时，`method_options.amount_ranges`
  保留两个区间且前端禁用中间空洞；旧 `single_min/single_max` 只暴露首个安全连续
  区间；
- 选源后禁用实例或修改凭证、支付类型、模式、限额时，下单前或网关调用前复核失败；
  当前用量查询失败时不得按零用量继续；
- 订阅 `1.14 USD × 7.25` 按后端一致规则显示 `8.27 CNY`，`1 CNY × 7%`
  手续费为 `0.07 CNY`；JPY/KRW 小数金额禁用，KWD/BHD/JOD 三位小数可输入且
  本金限额反推一致；
- 显式 `provider_key` 精确选源，缺失字段保持旧路由，非法组合返回
  `INVALID_PAYMENT_PROVIDER_SELECTION`；
- 官方微信 OAuth、Cookie 上下文、恢复令牌与同渠道二维码恢复保留
  `provider_key`，易支付微信不进入官方 OAuth，旧令牌继续兼容；
- `provider_key` 为空且最终选择官方微信时，协调器必须补载 OAuth AppID 后再校验，
  不能把合法 provider-agnostic 请求误判为 `NO_AVAILABLE_INSTANCE`；
- 管理端创建、编辑、启用和修改类型时不再拦截易支付与官方渠道同时启用；
- 管理端“用户渠道配置”显示全部已配置渠道（包括只含禁用实例的渠道），同渠道
  多实例只显示一行；空费率继承默认值，显式 `0` 显示免手续费，保存后正确回读；
- 渠道设置严格验证：名称不超过 100 个 Unicode 字符且无控制字符，费率为
  `0–100` 且最多两位小数；非法 ID、畸形 JSON、非对象 JSON 和未知字段失败关闭，
  未知但格式合法的渠道配置保留；
- `checkout-info.method_options` 返回最终 `display_name` 和 `fee_rate`，原
  `recharge_fee_rate` 仍为全局默认值；自定义名称在选择器和备用提示中优先于固定
  多语言文案；
- 显式 `provider_key` 的余额充值、订阅、订单费率和微信 OAuth/恢复上下文使用同一
  渠道费率；OAuth 短期签名上下文不可被查询参数篡改，回调恢复令牌保留显式
  `0` 和自定义费率，旧令牌无费率字段时继续兼容；不传 `provider_key` 的旧客户端
  仍按全局默认费率计算；
- 充值和订阅默认选择易支付，点击官方后载荷正确；失败不自动跨渠道重试，只显示
  手动备用提示；
- 金额或套餐变化导致当前渠道不适用时可以重选可用渠道；移动支付回退只在相同
  `payment_type/provider_key` 下创建桌面二维码订单，不能变成跨渠道自动重试；
- 旧 `methods` 接口、旧恢复快照、375px/桌面、亮色/暗色、键盘焦点、
  `aria-pressed` 和禁用状态均有回归；
- 候选树数据库边界检查必须确认无 Migration、Schema、实体字段或 SQL 变化。

## 10. 渠道监控分组名称与展示倍率

- 本站 API Key 能批量关联其当前分组默认倍率，倍率为 `0` 时仍视为有效；
- active 状态但已动态过期、动态耗尽配额、用户停用、分组停用、专属权限撤销、
  余额资格不成立、缺少有效订阅或订阅日/周/月运行时限额已超出的 Key 不返回自动
  倍率；已到重置时间的订阅窗口按清零后的只读投影判断，不因数据库维护尚未执行而
  误拒绝；
- 分组倍率修改后再次查询立即返回新值，不使用进程内缓存；
- 用户专属倍率与高峰倍率不改变监控卡片显示口径；
- 手动覆盖值优先于自动倍率，并在外部、失效、解密失败 Key 或批量查询失败时仍显示；
- 清空手动覆盖值后恢复自动解析，分组倍率修改后下一次查询立即生效；
- `group_name` 在有无倍率时都显示在模型后方、参与后台搜索并随复制保留；
- 空模板按 `{rate}x` 显示，并覆盖 `{rate}优先用`、`约{rate}x`、`{rate}`；
- 缺少或重复 `{rate}`、超过 64 字符的模板，以及非正数、NaN、Inf 覆盖值均拒绝；
- 状态与倍率在卡片右上角纵向显示，长徽标截断且 `title` 保留完整文本；模型行不被
  倍率挤占，并验证桌面和窄屏布局；
- 批量查询失败时监控列表仍成功，可用性、延迟和时间线保持原行为；
- 响应、日志和前端测试输出不包含 API Key；
- Candidate Tree 数据库边界检查必须识别 Migration、Schema、实体字段和 SQL 结构
  变化；发布前完成人工 Migration/Schema 审核，不得自动跳过数据库门禁；
- 人工审核通过的自定义结构变化必须逐文件登记到
  `.github/custom-database-exceptions.tsv`，并绑定 Vendor 基线提交、基线/候选 Blob、
  目标 SQL 语义摘要和完整变更摘要。未登记、摘要漂移、动态 SQL 或非结构型写入 SQL
  仍然失败关闭。

## 11. 分组最低余额门槛

- `balance` 低于或等于 `minimum_balance` 时拒绝，高于时允许；默认 `0` 完全关闭；
- 小于 `$0.01` 的差额最多显示八位小数，普通金额显示两位；相等时不显示
  “还差 `$0.00`”；
- 门槛开启时使用数据库最新余额，覆盖充值恢复以及一次请求结算后跨过门槛、下一次
  请求才暂停；关闭时不增加实时余额查询；
- 创建 Key、真正切换分组、普通计费、fallback 和批量生图新提交均校验；同分组
  编辑其他字段及批量生图幂等重放不因当前余额下降而失败；
- 管理员单 Key 真实切换使用数据库最新余额；同分组更新不检查。专属分组批量替换
  仅在事务内实际迁移 Key 时检查，零迁移不检查，拒绝时整个事务回滚；

## 13. 订阅本周期统计与套餐批量重置

- 计费的两条订阅累加路径都必须同时增加日/周/月窗口用量和 `cycle_usage_usd`；
- 手动重置必须清空所选窗口、保留 `cycle_usage_usd` 并将
  `manual_quota_reset_count` 原子加一；携带相同幂等键重放时不得重复增加次数；
- 第 25 天提前续订 30 天时，最终到期时间延长，但当前周期累计、重置次数和周期边界
  保持不变；第 30 天首次维护时才归档旧值、激活排队周期并清零新周期统计；
- 多次提前续订按开始时间顺序排队；并发跨越边界只能有一个请求完成周期推进，其他
  请求回读相同数据库快照；管理员时长调整只改变尾部周期；过期订阅可由最后一个
  `completed` 周期重新激活；退款失败必须精确恢复被取消的待生效周期、支付来源和套餐
  归属，不得只把天数加回前一个周期；
- PostgreSQL Integration 必须覆盖三项事务语义：单项同键重放只清零并计数一次；退款
  扣减后发生合法 `AdvanceCycle` 时快照恢复返回 stale 且不得覆盖新周期；扣减将导致过期
  时快照捕获与软删除在同一事务完成，无并发变更时可精确恢复删除状态和支付来源；
- 普通用户与管理员 DTO 都返回累计和次数，三个前端入口在次数为 `0` 时隐藏整行、
  大于 `0` 时显示两位小数金额，不显示周期日期或待生效周期数量；
- Migration 回填保留现有窗口用量，并在历史日志仍存在时纳入当前 legacy 周期累计；
  `usage_logs` 内容不迁移、不删除、不改写；
- 套餐开关覆盖默认关闭、创建、更新、管理端响应和编辑回显；Migration 197 必须保持
  `BOOLEAN NOT NULL DEFAULT FALSE`，不得批量开启历史套餐；
- Migration 198 必须只为 `user_subscription_cycles` 增加默认关闭的
  `manual_bulk_quota_reset_enabled`，不得自动更新历史支付、兑换、手动或 `legacy` 周期；
- 候选查询对 `payment` 只返回当前周期可由支付订单精确追溯到已开启套餐的订阅，覆盖
  套餐下架/售罄仍可入选、关闭开关、订单用户/分组不一致及套餐分组不一致的排除行为；
  `assignment/legacy` 只按当前周期手动开关入选，`redeem`、过期、暂停和撤销始终排除；
- 单个和批量手动分配覆盖开关省略时默认关闭、显式开启、过期后新周期按请求保存；活跃
  订阅重复分配不得借机修改资格，不一致时返回语义冲突；专用修改接口覆盖开启、关闭、
  重复设置、支付/兑换/过期/撤销拒绝，并验证有效期、窗口用量、累计和次数均不变化；
- 退款快照与 CAS 必须包含周期手动资格；调整当前周期尾部不得改变资格，提前续订的新
  周期不得继承旧周期资格，边界推进后只读取新周期保存的来源和资格；
- 第 25 天提前续订仍使用当前套餐资格，第 30 天边界后才使用待生效套餐；边界时执行
  批量重置必须先推进周期，再把重置次数记为新周期的第一次；
- 批量提交覆盖 ID 去重、事务锁内推进周期后重新校验资格、提交前关闭手动/套餐资格为
  跳过、单项失败不阻断其余项、日周月统一重置，以及同一幂等键重放不重复增加次数；
  PostgreSQL 用例还必须验证资格行锁提交前不会越过校验、边界推进后不符合资格的跳过
  结果会返回刷新后的订阅供缓存失效，以及符合资格时重置次数只计入新周期一次；修改
  手动资格若推进了周期，L1、Redis 与跨实例缓存必须在事务提交后失效；
  后端和前端均拒绝超过 300 个订阅，300 条
  最坏逐项结果序列化后必须小于默认 64 KiB 响应存储上限，逐项幂等记录与重置副作用
  必须位于同一事务；逐项身份必须由外层接口 Scope、管理员 Scope 与规范化键共同派生，
  并使用外层准确过期时间；覆盖同键跨单项/批量互不碰撞、同操作重放同步期限但不增加
  次数，以及外层过期后在订阅行锁内原子替换旧声明并再次执行；
- 前端覆盖分配开关默认关闭与提交、已有手动周期资格编辑、支付套餐/手动分配来源展示，
  以及候选加载、空状态、默认全选、半选、取消勾选、零选择禁用、仅提交所选项、
  超过 300 个候选时的选择上限和分批提示、提交期间锁定关闭/重复提交，以及成功、跳过、
  失败数量与逐项原因；
- 运行相关 Go Unit/Integration、DTO 与幂等测试、Custom Vitest、前端 typecheck/build、
  Ent 二次生成无漂移、数据库语义指纹和 Candidate Tree 边界检查。PostgreSQL 集成用例
  不具备本地数据库时只做带标签编译，并交由 Linux CI 执行。
